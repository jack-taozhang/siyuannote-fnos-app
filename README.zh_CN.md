# 本机存储 Local Storage（siyuan-localfs）

在思源笔记里可以直接浏览**「跑着思源的那台机器」**上的全部存储空间（NAS 上的 `/vol1`、`/vol00`…），
并且就地预览：DWG/DXF 图纸（借飞牛原生「CAD 看图」应用）、Office / PDF 在线预览（借飞牛官方「Office 文档」应用）、图片 / 音视频内联播放。

## 它解决什么问题

思源笔记以 Docker 方式运行时**看不见宿主的存储空间**（容器只挂了三个目录）—— 这正是"必须绕路"的根因。
本插件的数据面由「思源笔记」飞牛应用（`siyuannote`）里的 `local-fs` 服务提供，它随思源一起起停，
**内核不再自带查看器**（原来那份随应用打包的 22MB 内置查看器已删除）。
页面改为**借用飞牛原生的三个应用**，形态完全统一：

| 用途 | 借用的飞牛应用 | 它的端口 | 挂在思源下的通道 |
| --- | --- | --- | --- |
| CAD / DWG / DXF | 原生「CAD 看图」`fnos-dwg-viewer` | 8020 | `/localfs/cad/*` |
| Office / PDF | 官方「Office 文档」`trim.docs` | 5666 | `/localfs/docs/*` |
| 其余格式兜底 | 原生「文件预览」`fnos-file-viewer` | 8030 | `/localfs/fv/*` |

三条链路**一律走思源反代的同源通道**（`:6806`），不再直连各自应用的端口。
理由有二：手机经外网穿透时只映射了 6806 这一个端口，直连 8020 / 8030 / 5666 根本够不到；
而且内嵌预览要靠**同源 iframe 注入样式**，才能把查看器自带的外壳（工具栏 / 命令行 / 文件树）藏掉 ——
一旦跨源，注入会静默失效、外壳全部冒回来。

服务挂在**同一个源**下的 `/localfs/*` 通道上，所以三种访问方式都能用：

| 访问方式 | 插件连接的地址 |
| --- | --- |
| 网页版 / 手机（含飞牛 App 外网穿透） | 同源 `/localfs`（穿透只映射了思源这一个端口） |
| 网页版（局域网 IP / ZeroTier） | 同源 `/localfs` |
| 思源**桌面客户端** | 需在设置里填 `http://<NAS 地址>:6806/localfs`（**别填 :8021** —— 穿透只映射 6806，且绕过反代就拿不到 Office 的登录态） |

地址是**自动探测**的：先试上次成功过的，再依次试同源带前缀、同源裸根、`:8021`，谁先答对就用谁。
都连不上时面板会给出可填地址的引导页（桌面客户端属于这一类，因为它的页面跑在本机内核上，探不到外面）。

## 预览方式

| 文件类型 | 预览方式 |
| --- | --- |
| `.dwg` `.dxf` | 飞牛原生「CAD 看图」应用（同源通道 `/localfs/cad/open?path=`） |
| Office / PDF（doc/docx、xls/xlsx、ppt/pptx、wps、et、dps、odt/ods/odp、epub、djvu…） | 飞牛官方「Office 文档」应用（同源通道 `/localfs/docs/preview?path=`）。可读可写由**文件自身的权限**决定 |
| 图片 / 音频 / 视频 | 浏览器原生 |
| 文本 / 代码 / Markdown / CSV | 直接读取前 512 KB 显示 |
| 其它（压缩包 / 3D / OFD…） | 飞牛原生「文件预览」应用兜底 |

## 怎么用

- **桌面端 / 网页版**：右侧边栏的「本机存储」图标。
- **手机**：命令面板里的「打开本机存储」（移动端没有侧边栏停靠，这里用全屏浮层代替）。
- 单击文件 = 预览；**右键 / 长按** = 菜单（预览、在页签中打开、嵌入到文档、下载、在浏览器中打开、复制路径 / 链接）。
- 文件树**默认全收拢** —— 打开只看到几个卷名，点哪个展开哪个（不再记住上次展开的目录）。
- 设置：浏览面板右上角的齿轮。**这是唯一的设置入口**，只有三块：
  服务地址（含「测试连接」与当前状态） / 飞牛登录态 / 常用文件夹。

## 注意事项

- 这个服务本身**不做鉴权**（以 root 直读全盘，靠"谁能连到这个端口"来界定）
  ⇒ **不要**把 8021 暴露到公网。
- **Office 文档要飞牛的登录态**，这是官方那套应用自己的要求。浏览器里连着飞牛时，
  同一主机上的 Cookie 会自动带上，直接就能打开；**思源桌面客户端**跑在本机内核上、
  看不到那份登录态，所以设置里有一个「同步飞牛登录态」：在能登录飞牛的浏览器里点一下，
  凭据就存到 NAS 上（文件权限 `600`，只挑 `ost` / `osrt` / `fnos-token` / `fnos-long-token`
  四个名字，接口永不回显凭据内容），反代在请求没带凭据时自动补上、自带凭据时绝不覆盖。
  全程零输入、不接触密码、不逆向飞牛的登录协议。

## 开发

```
npm run build      # 打包到本机思源 D:/Software/SiYuan/data/plugins/siyuan-localfs
npm run build:repo # 输出到仓库 dist/（留档）
npm run pack       # 生成 dist-package/siyuan-localfs.zip（含 8 项自检）
```

源码在 `src/` 下，入口是仓库根目录的 `index.js`。
**构建产物也叫 `index.js`，但只能写到安装目录或 `dist/`，绝不能覆盖仓库根的那个** ——
那是入口源码（构建器每次动手前都会断言这一点）。

打包成单文件不是风格问题：思源给插件的 `require` **只认 `siyuan`**，其余一律委托给 Electron 的
`window.require`（它的解析基准是渲染进程自己的 bundle，不是插件目录），所以 `require("./src/x.js")`
必然失败，而且**只报在浏览器 console**，`siyuan.log` 里干干净净。
